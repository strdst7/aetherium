<objective>
Implement the identity constraint engine that applies identity rules (allowed/forbidden behaviors) to outputs and produces a structured trace of rule checks.

Purpose: Identity rules from SigilIdentity.config.customRules must be evaluated at every reasoning step. This engine checks outputs against constraints and produces violations if rules are broken.
Output: IdentityConstraintEngine with rule evaluation, violation detection, and trace integration.
</objective>

<tasks>
1. Create `api/src/services/identity-constraints.ts` with:
   - `IdentityConstraintEngine` class
   - `evaluate(output: string, identity: SigilIdentity)` method that:
     - Checks output against identity.config.customRules
     - Returns `IdentityConstraintResult` with violations, ruleChecks, passed
   - Rule formats:
     - "must contain: X" → checks if output contains X
     - "must not contain: X" → checks if output does NOT contain X
     - "tone: X" → validates tone matches (simple string check)
     - Any other rule → logged as "unknown rule type"
   - `RuleCheck` type: { rule: string, passed: boolean, detail: string }
   - `IdentityConstraintResult` type: { passed: boolean, violations: Violation[], ruleChecks: RuleCheck[] }

2. Update `ReflectiveService.evaluate()` to:
   - Accept optional `identity` parameter
   - If identity provided, run constraint engine and merge violations
   - Add `identityRuleChecks` to the returned result
   - Update `ReflectiveCheckResult` interface to include `identityRuleChecks?: RuleCheck[]`

3. Create `identity-constraints.test.ts` with:
   - Test: "must contain" rule passes when output contains text
   - Test: "must contain" rule fails when output missing text
   - Test: "must not contain" rule passes when output clean
   - Test: "must not contain" rule fails when output contains forbidden text
   - Test: multiple rules evaluated together
   - Test: unknown rules are logged but not flagged as violations
</tasks>
