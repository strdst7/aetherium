## Decision Context

- **D-06:** Agent Builder wraps the existing `Orchestrator`. Delegates memory, prompt, reflection to existing Orchestrator.
- **D-08:** MCP server connects as standalone process via stdio transport.
- **D-09:** Agent-managed lifecycle: starts MCP server on startup, monitors it, restarts if crashes.
- **D-10:** MCP server path via `MCP_SERVER_PATH` env var.
- **D-11:** Tools auto-discovered from MCP server at startup and registered into Agent Builder.
- **D-12:** If MCP server unavailable or tool call fails, return structured error in `ReasonResponse` with `toolExecutionTrace`. No fallback.
</context>

Create `api/src/services/mcp-client.ts` implementing the MCP client per D-08, D-09, D-10, D-11.

1. Define types:
```typescript
export type MCPTool = {
  name: string;
  description: string;
  parameters?: Record<string, any>;
};

export type MCPSchema = {
  tools: MCPTool[];
  // Schema discovery results (e.g., database collections)
  collections?: string[];
};

export type ToolExecutionResult = {
  success: boolean;
  data?: any;
  error?: string;
};
```

2. Implement `MCPClient`:
   - Constructor accepts `serverPath` (default `process.env.MCP_SERVER_PATH`)
   - `start()`: Spawns the MCP server as a child process using `child_process.spawn`. The server communicates via stdio (stdin/stdout). Use a simple JSON-RPC-like protocol over stdio (e.g., newline-delimited JSON messages).
   - `discoverTools()`: Sends a `discover` message to the MCP server and returns the list of tools (`MCPTool[]`). Parse the response from stdout.
   - `executeTool(name, arguments)`: Sends an `execute` message with the tool name and arguments. Returns `ToolExecutionResult`.
   - `stop()`: Kills the child process gracefully.
   - `isHealthy()`: Returns true if the child process is running.
   - `getSchema()`: Returns `MCPSchema` with discovered tools and collections.

3. The MCP stdio protocol is simple JSON-RPC over newline-delimited JSON:
   - Request: `{ "jsonrpc": "2.0", "id": 1, "method": "discover", "params": {} }\n`
   - Response: `{ "jsonrpc": "2.0", "id": 1, "result": { "tools": [...] } }\n`
   - Request: `{ "jsonrpc": "2.0", "id": 2, "method": "execute", "params": { "name": "query", "arguments": {...} } }\n`
   - Response: `{ "jsonrpc": "2.0", "id": 2, "result": { "success": true, "data": [...] } }\n`

4. Error handling:
   - If `MCP_SERVER_PATH` is not set, throw an error on start.
   - If the server process exits unexpectedly, set `isHealthy() = false` and log the error.
   - If a tool call fails, return `{ success: false, error: string }`.

5. Monitoring: Use `process.on('exit', ...)` to restart the server with exponential backoff (max 3 retries, then give up). Log restart attempts.

6. Write tests in `api/src/services/mcp-client.test.ts`:
   - Mock `child_process.spawn` to simulate the MCP server
   - Test discovery, execution, crash handling, and error cases
   - Do NOT require a real MCP server executable

1. Define the AgentBuilder interface:
```typescript
export interface AgentBuilderConfig {
  enableTools?: boolean;
  maxToolIterations?: number;
}

export interface AgentBuilderResult {
  response: ReasonResponse;
  toolExecutionTrace?: ToolExecutionTrace[];
}
```

2. Define `ToolExecutionTrace`:
```typescript
export type ToolExecutionTrace = {
  step: number;
  toolCall: ToolCall;
  result: ToolExecutionResult;
  timestamp: string;
};
```

3. Implement `AgentBuilder`:
   - Constructor accepts `orchestrator: Orchestrator`, `mcpClient: MCPClient`, and optional `config: AgentBuilderConfig`
   - `initialize()`: Calls `mcpClient.start()` and `mcpClient.discoverTools()`. Stores discovered tools.
   - `execute(req: ReasonRequest, config?: AgentBuilderConfig): Promise<AgentBuilderResult>`:
     - If `enableTools` is false or MCP client is unhealthy, delegates to `orchestrator.process()` and returns the standard response.
     - If `enableTools` is true and MCP client is healthy:
       1. Call `orchestrator.process()` to get the initial reasoning context (memory, prompt)
       2. Use the Gemini provider to call `generateWithTools()` with the discovered tools
       3. If `toolCalls` are returned, execute each tool via `mcpClient.executeTool()`
       4. Record each step in `toolExecutionTrace`
       5. Call `generateWithTools()` again with the tool results
       6. Repeat up to `maxToolIterations` (default 5)
       7. Return the final response with `toolCalls`, `toolResults`, and `toolExecutionTrace` populated
   - `shutdown()`: Calls `mcpClient.stop()`

4. Error handling per D-12:
   - If MCP server is unavailable: return structured error in `ReasonResponse` with `toolExecutionTrace` showing the failure
   - If a tool call fails: include the error in `toolExecutionTrace` and continue or stop (document the choice)
   - No fallback to non-tool reasoning path when tools are explicitly enabled

5. The `ReasonResponse` extension will be done in Plan 3, so for now define the types in agent-builder.ts and re-export them.

6. Write tests in `api/src/services/agent-builder.test.ts`:
   - Mock `Orchestrator` and `MCPClient`
   - Test standard reasoning path (no tools)
   - Test tool-enabled reasoning path with multiple tool iterations
   - Test MCP server failure handling
   - Test maxToolIterations limit

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Elevation of Privilege | MCPClient | mitigate | MCP server path from env var only; validate executable exists before spawn |
| T-02-02 | Denial of Service | MCPClient | mitigate | Exponential backoff on restart (max 3 retries); process kill timeout prevents zombie processes |
| T-02-03 | Tampering | MCPClient | accept | stdio transport is local to host; no network tampering risk |
| T-02-04 | Information Disclosure | AgentBuilder | mitigate | Tool execution trace includes only tool names and results, not raw system output |
| T-02-05 | Repudiation | AgentBuilder | mitigate | Tool execution trace is immutable array with timestamps |
| T-02-06 | Denial of Service | AgentBuilder | mitigate | maxToolIterations limits the tool loop to prevent infinite recursion |
</threat_model>
