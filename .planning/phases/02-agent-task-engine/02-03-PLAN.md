  <action>
    Add a new `executeTask` method to the `AgentBuilder` class. The method should:

    1. Accept `req: ReasonRequest` and `config?: AgentBuilderConfig` as parameters.
    2. Return `Promise<AgentBuilderResult>` (same as `execute`).
    3. Build an `OrchestratorRequest` from the `ReasonRequest` (same as `execute`).
    4. Call `this.orchestrator.generatePlan(orchestratorReq, this.tools)` to get a `TaskPlan`.
    5. Initialize tracking structures:
       - `toolExecutionTrace: ToolExecutionTrace[] = []`
       - `toolCalls: ToolCall[] = []`
       - `toolResults: ToolExecutionResult[] = []`
       - `completedSteps: number[] = []`
       - `failedSteps: number[] = []`
    6. Iterate through `plan.steps` (up to `config.maxTaskIterations` or 20 steps):
       - For each step, call `this.mcpClient.executeTool(step.tool, step.args)`
       - If successful: add to `completedSteps`, push to `toolExecutionTrace`, `toolCalls`, `toolResults`
       - If failed: add to `failedSteps`, push error result to trace
    7. Determine `planStatus`:
       - `complete`: all steps succeeded
       - `partial`: some steps succeeded, some failed
       - `failed`: all steps failed or plan was empty
    8. Synthesize actions from `toolResults` using `synthesizeActions` (implemented in next task).
    9. Build the `ReasonResponse` with:
       - `plan`: the generated `TaskPlan`
       - `actions`: synthesized actions
       - `planStatus`: determined status
       - `toolCalls`, `toolResults`, `toolExecutionTrace`: from execution
       - `output`: human-readable summary of results (e.g., "Completed 2 of 3 steps. Updated 42 users.")
    10. Return `AgentBuilderResult` with the response.
    11. Add error handling: if `generatePlan` fails, return an error response with `planStatus: "failed"`.
    12. Add JSDoc comment to the method.

    Import `TaskPlan`, `PlanStep`, `Action`, `PlanStatus` from `../controllers/reason`.

    Import `ToolExecutionResult` from `./mcp-client`.

  <name>task 2: Implement retry logic and action synthesis</name>
  <files>api/src/services/agent-builder.ts</files>
  <action>
    Implement two helper methods in `AgentBuilder`:

    1. **retryStep(step: PlanStep): Promise<ToolExecutionResult>**
       - Called when a step fails in `executeTask`.
       - Retries the same step with adjusted arguments:
         - Add `_retry: true` to args to indicate retry
         - Add `_original_error: <error_message>` to args for context
       - If retry succeeds, return the success result.
       - If retry fails, return the error result (do not throw; let `executeTask` continue).
       - Log retry attempts with `console.warn`.

    2. **synthesizeActions(toolResults: ToolExecutionResult[], toolCalls: ToolCall[]): Action[]**
       - Maps each tool result to an `Action` based on the tool name:
         - `query` → `type: "report"`, title: "Query Result", data: toolResult.data
         - `update` → `type: "update"`, title: "Record Update", data: toolResult.data
         - `insert` → `type: "trigger"`, title: "Record Created", data: toolResult.data
         - `delete` → `type: "trigger"`, title: "Record Removed", data: toolResult.data
         - Default → `type: "notify"`, title: "Tool Result", data: toolResult.data
       - For `report` actions, set `format: "json"` if data is an object.
       - For `update` actions, set `format: "count"` if data is a number (e.g., number of records updated).
       - Actions are ordered by execution order.

    Update `executeTask` to use `retryStep` when a step fails:
    ```typescript
    let result = await this.mcpClient.executeTool(step.tool, step.args);
    if (!result.success) {
      result = await this.retryStep(step);
    }
    ```

    Update `executeTask` to call `synthesizeActions` after all steps are executed:
    ```typescript
    const actions = this.synthesizeActions(toolResults, toolCalls);
    ```

    Add JSDoc comments to both helper methods.

| Boundary | Description |
|----------|-------------|
| User request → plan generation | Untrusted input drives multi-step execution |
| Tool execution → retry logic | Failed operations may expose error details |
| Action synthesis → response | Untrusted tool results transformed into structured actions |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-08 | Injection | executeTask | mitigate | Tool names validated by generatePlan; retryStep only retries same tool with same args + metadata |
| T-02-09 | Denial of Service | executeTask | mitigate | maxTaskIterations limits steps to 20; prevents infinite loops |
| T-02-10 | Information Disclosure | retryStep | accept | Error messages in `_original_error` are tool-level, not system-level; no sensitive data leakage |
| T-02-11 | Repudiation | executeTask | accept | toolExecutionTrace captures all steps; audit trail is Phase 8 scope |

</threat_model>
