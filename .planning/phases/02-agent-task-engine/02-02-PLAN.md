  <name>task 1: Add generatePlan method to Orchestrator</name>
  <files>api/src/services/orchestrator.ts</files>
  <action>
    Add a new `generatePlan` method to the `Orchestrator` class. The method should:

    1. Accept an `OrchestratorRequest` and an array of `ToolDefinition[]` as parameters.
    2. Use the same memory retrieval and embedding logic as `processWithTools` (compute embedding, retrieve memories, build prompt).
    3. Select a provider that supports `generateWithTools` and `requireToolUse: true`.
    4. Build a system prompt that instructs the model to generate a structured plan:
       ```
       You are a task planner. Given the user request and available tools, generate a JSON plan.
       The plan must be an array of steps. Each step has: tool (string), args (object), expected_result (string).
       Only use the available tools. Return ONLY the JSON array, no markdown.
       ```
    5. Call `provider.generateWithTools` with the plan-generation prompt and the available tools.
    6. Parse the model's response as JSON. The response should be an array of `{ tool, args, expected_result }` objects.
    7. Convert the parsed array into a `TaskPlan` object with `steps` array (each step numbered sequentially starting from 1).
    8. Return the `TaskPlan`.
    9. Add error handling: if the model response is not valid JSON, is not an array, or refers to tools not in the available tools list, throw an error with a descriptive message.
    10. Add JSDoc comment to the method.

    Import `TaskPlan` and `PlanStep` from `../controllers/reason` (they will be available after Plan 01 executes).
    Import `ToolDefinition` from `../adapters/ai-adapter`.

    Example expected output for "Find all users who haven't logged in for 30 days and set their status to inactive":
    ```json
    {
      "steps": [
        {
          "stepNumber": 1,
          "tool": "query",
          "args": { "collection": "users", "filter": { "lastLogin": { "$lt": "30 days ago" } } },
          "expected_result": "List of inactive users"
        },
        {
          "stepNumber": 2,
          "tool": "update",
          "args": { "collection": "users", "filter": { "lastLogin": { "$lt": "30 days ago" } }, "update": { "status": "inactive" } },
          "expected_result": "Updated user statuses"
        }
      ]
    }
    ```

<task type="auto">
  <name>task 3: Add error handling and validation for plan generation</name>
  <files>api/src/services/orchestrator.ts</files>
  <action>
    In the `generatePlan` method, add robust validation logic:

    1. **Tool validation**: After parsing the JSON, verify each step's `tool` exists in the available `tools` array. If a step references an unknown tool, throw an error: `Plan step ${stepNumber} references unknown tool: ${toolName}`.
    2. **Args validation**: Ensure each step's `args` is a plain object (not null, not an array). If invalid, throw an error: `Plan step ${stepNumber} has invalid args`.
    3. **Max steps limit**: Reject plans with more than 50 steps to prevent abuse. If exceeded, throw: `Plan exceeds maximum of 50 steps`.
    4. **JSON extraction**: If the model response contains markdown code blocks (e.g., ```json ... ```), extract the JSON content before parsing. Use a regex to extract JSON between triple backticks.
    5. **Graceful fallback**: If plan generation fails, return a `TaskPlan` with a single step that uses the `query` tool with the original request as the query text. This ensures the agent can still attempt to handle the request.
    6. **Logging**: Add `console.log` or `console.warn` for plan generation errors (consistent with existing codebase patterns).

    Add a helper function `extractJSONFromResponse(text: string): string` to handle markdown extraction.
  </action>
