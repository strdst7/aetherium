<task type="auto">
  <name>task 3: Create comprehensive health endpoint</name>
  <files>api/src/routes/health.ts</files>
  <action>
Create `api/src/routes/health.ts` that replaces the simple health check with a comprehensive status endpoint:

1. Export `createHealthRouter(services)` that takes an object containing:
   - `mcpClient: MCPClient` (for MCP connection status)
   - `providerRegistry: ProviderRegistry` (for provider health)
   - `memoryService: MemoryService` (for DB connection status)
   - `agentBuilder: AgentBuilder` (for agent initialization status)

2. Implement `GET /health` that returns `HealthResponse`:
   ```json
   {
     "status": "ok" | "degraded" | "down",
     "timestamp": "2026-06-06T...",
     "version": "1.0.0",
     "services": {
       "mongodb": { "status": "connected", "latencyMs": 12 },
       "mcp": { "status": "connected" },
       "gemini_provider": { "status": "healthy" },
       "ollama_provider": { "status": "healthy" },
       "agent_builder": { "status": "initialized" }
     }
   }
   ```
3. Status logic:
   - `ok`: All critical services (mongodb, at least one provider) are healthy
   - `degraded`: MCP is down but providers are up (tool-use disabled but reasoning works)
   - `down`: No providers available OR MongoDB unreachable
4. Check each service with a lightweight operation (e.g., `memoryService.isConnected()`, `mcpClient.isHealthy()`, provider `healthCheck()`, `agentBuilder` initialization flag)
5. Measure latency for MongoDB with a simple ping or timestamp check
6. Export `createApiInfoRouter()` for `GET /v1/info` returning `ApiInfoResponse`:
   ```json
   {
     "apiVersion": "1.0.0",
     "supportedVersions": ["1.0.0"],
     "features": ["reasoning", "tool-use", "task-mode", "reflection", "multi-agent"],
     "documentationUrl": "/docs"
   }
   ```
7. Both routers should set appropriate Cache-Control headers (e.g., `no-cache` for health, `max-age=3600` for info)

Note: You will need to import types from the respective service files. Use the existing imports from `api/src/index.ts` as reference for available methods.
  </action>
  <verify>
    <automated>test -f api/src/routes/health.ts && grep -q "createHealthRouter" api/src/routes/health.ts && grep -q "createApiInfoRouter" api/src/routes/health.ts && grep -q "services" api/src/routes/health.ts</automated>
  </verify>
  <done>Health router exists, returns comprehensive status with service breakdown, and API info endpoint shows version/features</done>
</task>
