2. Create `versionNegotiation` middleware that:
   - Reads `Accept-Version` header first (e.g., `Accept-Version: v1` or `Accept-Version: 1.0.0`)
   - Falls back to `api-version` query parameter
   - Falls back to path extraction (e.g., `/v1/reason` → version v1)
   - Normalizes "v1" to "1.0.0", "v2" to "2.0.0" etc.
   - If version is unsupported: return 406 Not Acceptable with ProblemDetails body:
     ```json
     {
       "type": "https://aetherium.dev/errors/unsupported-version",
       "title": "Unsupported API Version",
       "status": 406,
       "detail": "Version X is not supported. Supported versions: 1.0.0",
       "instance": "<request-id>"
     }
     ```
   - If version is supported or not specified: set `res.locals.apiVersion = "1.0.0"` and call `next()`
3. Export `extractVersion(req): string` helper function

The middleware should run BEFORE route handlers. It should NOT block requests that don't specify a version (default to current version).

     ```json
     }
     ```

   - For reasoning errors (from ReasonController):
     ```json
     {
       "type": "https://aetherium.dev/errors/reasoning-error",
       "title": "Reasoning Error",

       "detail": "<error message>",
       "instance": "<request-id>"
     }
     ```
   - For tool execution errors:
     ```json
     {
       "type": "https://aetherium.dev/errors/tool-execution-error",
       "title": "Tool Execution Error",
       "status": 502,
       "detail": "<error message>",
       "instance": "<request-id>"
     }
     ```
   - For internal server errors:
     ```json
     {
       "type": "https://aetherium.dev/errors/internal-server-error",
     ```
