Create `api/src/services/sovereign-halo.ts` with `SovereignHaloService` class:

1. Constructor dependencies:
   - `constraintEngine: IdentityConstraintEngine`
   - `mythicModule: MythicModule`
   - `options?: HaloValidationOptions` (optional, merged with defaults)

2. Default options (static constant):
   ```typescript
   DEFAULT_OPTIONS: HaloValidationOptions = {
     maxAttempts: 3,
     temperaturePenalty: 0.1,
     requireSymbolicAnchors: true,
     toneTolerance: 0.5,
     skipSafetyCheck: false,
   }
   ```

3. `async validate(output: string, identity: SigilIdentity, attemptNumber?: number): Promise<ValidationReport>`:
   - Get `MythicIdentitySchema` via `this.mythicModule.generateSchema(identity)`
   - Run all three check categories in parallel (Promise.all):
     a. `checkForbiddenBehaviors(output, identity)`
     b. `checkToneDeviation(output, schema)`
     c. `checkSymbolicDrift(output, schema)`
   - Aggregate all checks into a single array
   - Compute `passedCount`, `failedCount`, `totalCount`
   - Compute `confidenceScore` as weighted average of check confidences, using `ValidationRule.weight`:
     ```typescript
     confidenceScore = sum(check.confidence * check.rule.weight) / sum(check.rule.weight)
     ```
   - Set `status` to "passed" if `failedCount === 0`, else "failed"
   - Return `ValidationReport` with all fields, including `identityId: identity.id`, `validatedAt: new Date().toISOString()`, and optional `attemptNumber`

4. `checkForbiddenBehaviors(output: string, identity: SigilIdentity): ValidationCheck[]`:
   - Delegate to `this.constraintEngine.evaluate(output, identity)`
   - For each `ruleCheck` in the result, create a `ValidationCheck`:
     - `rule`: `{ id: "forbidden_${index}", name: ruleCheck.rule, category: "forbidden", weight: 1.0 }`
     - `passed`: `ruleCheck.passed`
     - `detail`: `ruleCheck.detail`
     - `confidence`: `ruleCheck.passed ? 1.0 : 0.0`
   - If `skipSafetyCheck` is false, also add a basic safety check:
     - Check for common profanity patterns (use a small built-in array: ["damn", "hell", "crap"])
     - `rule`: `{ id: "safety_profanity", name: "No Profanity", category: "safety", weight: 0.8 }`
     - `passed`: output does not contain any profanity words
     - `confidence`: 1.0 if passed, else 0.5

5. `checkToneDeviation(output: string, schema: MythicIdentitySchema): ValidationCheck[]`:
   - Expected tone register: `schema.tone.register`
   - Detected tone: use a simple heuristic:
     - Count "formal" words ("shall", "hereby", "furthermore", "pursuant", "notwithstanding") vs "informal" words ("gonna", "wanna", "yeah", "cool", "awesome")
     - If expected is "formal" and formal count > informal count → detected = "formal"
     - If expected is "playful" and informal count > formal count → detected = "playful"
     - Otherwise → detected = "neutral"
   - Compute `deviationScore`: 0.0 if detected === expected, 0.5 if partially aligned, 1.0 if completely opposite
   - Return a single `ValidationCheck`:
     - `rule`: `{ id: "tone_deviation", name: "Tone Deviation", category: "tone", weight: 0.9 }`
     - `passed`: `deviationScore <= this.options.toneTolerance`
     - `detail`: `Expected tone: ${expected}, detected: ${detected}, deviation: ${deviationScore}`
     - `confidence`: `1.0 - deviationScore`
     - `metadata`: `{ expectedTone: expected, detectedTone: detected, deviationScore }`

6. `checkSymbolicDrift(output: string, schema: MythicIdentitySchema): ValidationCheck[]`:
   - Expected anchors: `schema.symbolicAnchors.map(a => a.concept)`
   - If `requireSymbolicAnchors` is true AND anchors array is non-empty:
     - For each anchor concept, check if it appears (case-insensitive) in output
     - `detectedAnchors`: anchors found
     - `missingAnchors`: anchors not found
     - `driftScore`: `missingAnchors.length / expectedAnchors.length` (0 if all found)
   - If anchors array is empty OR `requireSymbolicAnchors` is false → auto-pass
   - Return a single `ValidationCheck`:
     - `rule`: `{ id: "symbolic_drift", name: "Symbolic Drift", category: "symbolic", weight: 0.7 }`
     - `passed`: `driftScore === 0` (or auto-pass when no anchors)
     - `detail`: `Expected anchors: [${expectedAnchors.join(", ")}], found: [${detectedAnchors.join(", ")}]`
     - `confidence`: `1.0 - driftScore`
     - `metadata`: `{ expectedAnchors, detectedAnchors, missingAnchors, driftScore }`

7. `generateFailureReport(validationReport: ValidationReport, attemptCount: number, identity: SigilIdentity): FailureReport`:
   - Extract `violationSummary` from validation report: all failed checks' detail strings
   - `safeFallbackMessage`: use identity config if available, else default:
     ```typescript
     identity.config?.customRules?.find(r => r.toLowerCase().startsWith("fallback:"))?.split(":")[1]?.trim()
     || "The generation could not satisfy identity constraints. Please refine your request."
     ```
   - Return `FailureReport` with all fields populated

8. Export `MAX_HALO_ATTEMPTS = 3` as a named constant.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Raw LLM output → validate() | Untrusted text crosses into validation pipeline |
| Identity config → validation rules | User-controlled rules influence pass/fail |
| ValidationReport → API response | Validation results exposed to caller |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-03 | Spoofing | safeFallbackMessage | mitigate | Static message; never includes raw unvalidated output per D-12 |
| T-07-04 | Tampering | validation confidence | accept | Confidence is advisory; enforcement uses passed/failed booleans |
| T-07-05 | Denial of Service | checkToneDeviation string scanning | mitigate | Bounded string scans; no regex backtracking; output length capped implicitly by LLM maxTokens |
| T-07-06 | Information Disclosure | ValidationCheck.metadata | accept | Metadata contains only rule matching info, no PII or secrets |
| T-07-07 | Elevation of Privilege | skipSafetyCheck option | accept | Option is caller-controlled in same trust domain; no privilege escalation |
</threat_model>
