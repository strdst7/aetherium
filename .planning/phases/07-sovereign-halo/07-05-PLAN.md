2. Add a private helper method `validateAgentOutput()`:
   ```typescript
   private async validateAgentOutput(
     output: string,
     identity: SigilIdentity | null,
     agentName: string
   ): Promise<{ valid: boolean; report?: ValidationReport; regeneratedOutput?: string }>
   ```
   Implementation:
   - If `sovereignHalo` is undefined OR `identity` is null → return `{ valid: true }` (backward compatibility)
   - Validate the output: `const report = await this.sovereignHalo.validate(output, identity);`
   - If `report.status === 'passed'` → return `{ valid: true, report }`
   - If failed, attempt ONE regeneration for council agents (council agents get 1 attempt, not 3 — the Orchestrator handles the 3-attempt loop for the final path):
     - Build tightened prompt: append violations to the agent's input
     - Re-run the agent's act method with the tightened input
     - Validate the regenerated output
     - If passed → return `{ valid: true, report: newReport, regeneratedOutput: newOutput }`
     - If still failed → return `{ valid: false, report: newReport }`
   - Log each validation attempt: `console.log(\`[Sovereign Halo] ${agentName} validation: ${report.status} (confidence: ${report.confidenceScore})\`)`

3. Update `runFlow()` method:
   - After loading identity, keep the existing flow but wrap each agent's output with validation:
   
   Step 1 (Archivist) — keep existing:
   ```typescript
   const arch = await this.archivist.act(input, baseCtx);
   const memories = arch.meta?.results ?? [];
   ```
   Add validation after archivist output:
   ```typescript
   const archValidation = await this.validateAgentOutput(arch.output, identity, "Archivist");
   const archivistResult = archValidation.regeneratedOutput || arch.output;
   ```
   
   Step 2 (Sigil Keeper) — keep existing:
   ```typescript
   const keeper = await this.sigilKeeper.act(input, ctxWithMem);
   ```
   Add validation after sigil keeper output:
   ```typescript
   const keeperValidation = await this.validateAgentOutput(keeper.output, identity, "SigilKeeper");
   const keeperResult = keeperValidation.regeneratedOutput || keeper.output;
   ```
   Update the revision check to use `keeperResult`:
   ```typescript
   const finalPrompt = keeperResult === "REVISE" || keeper.output === "REVISE"
     ? `${input}\n\n(Respect these constraints: ${JSON.stringify(keeper.meta?.violations || keeperValidation.report?.checks.filter(c => !c.passed).map(c => c.detail))})`
     : input;
   ```
   
   Step 3 (Narrator) — keep existing:
   ```typescript
   const final = await this.narrator.act(finalPrompt, ctxWithMem);
   ```
   Add validation after narrator output:
   ```typescript
   const narratorValidation = await this.validateAgentOutput(final.output, identity, "Narrator");
   const narratorResult = narratorValidation.regeneratedOutput || final.output;
   ```

4. Update the return object:
   ```typescript
   return {
     archivist: { ...arch, output: archivistResult, validationReport: archValidation.report },
     sigilKeeper: { ...keeper, output: keeperResult, validationReport: keeperValidation.report },
     narrator: { ...final, output: narratorResult, validationReport: narratorValidation.report },
     identity: identity ? { id: identity.id, name: identity.name, version: identity.version } : undefined,
   };
   ```
   Note: `validationReport` is optional and only present when `sovereignHalo` is active.

5. Ensure backward compatibility:
   - When `sovereignHalo` is undefined, the return object must have the same shape as before (no validationReport fields)
   - All existing fields (arch, sigilKeeper, narrator, identity) remain unchanged in structure

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-17 | Spoofing | Agent output substitution | mitigate | Regenerated output replaces original only after validation passes; failed outputs are flagged, not silently used |
| T-07-18 | Tampering | validationReport in response | accept | Reports contain only rule metadata, no sensitive data |
| T-07-19 | Denial of Service | Per-agent regeneration | mitigate | Council agents get 1 regeneration attempt (not 3), preventing multiplicative latency increase |
| T-07-20 | Information Disclosure | Agent context leakage | accept | Agent contexts are internal to the council flow; no external leakage |
</threat_model>
